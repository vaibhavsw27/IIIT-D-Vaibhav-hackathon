# Data

Everything the prototype needs to run offline is in this folder. Only public or synthetic data is used.

## Files

| Path | What it is | Committed? |
|---|---|---|
| `sample/news_sample.csv` | 210 synthetic news headlines (cols: `timestamp, source, title, text, url, tickers`) covering all 15 tickers and all 10 event types, 1 Jul - 29 Aug 2022 | yes |
| `sample/tweets_sample.csv` | 210 synthetic tweets in the Kaggle tweets format (`Date, Tweet, Stock Name, Company Name`) | yes |
| `raw/prices.csv` | Daily adjusted closes from Yahoo Finance (`yfinance`) for the 15 stocks + `^GSPC`, Sep 2021 - Oct 2022 | yes (small cache) |
| `raw/all-data.csv` | Kaggle financial news sentiment (labelled) | no - download |
| `raw/stock_tweets.csv` | Kaggle stock tweets | no - download |
| `signals.json`, `signals.csv` | Demo signals (sample + live GDELT runs), schema in the main README | yes |
| `signals_historical.csv.gz` | All 54,600 signals from the Kaggle tweets run (same columns) | yes |
| `weights.csv.gz`, `rebalance_log.csv.gz` | Index weight path and the reason for every change, per run (`sample`, `historical`, `live`) | yes |
| `signals.db` | SQLite with tables `signals`, `documents`, `weights`, `rebalance_log`. **Not committed**: rebuilt automatically from the files above on first use (~2 s) | no |
| `backtest_results*.csv` | Daily returns and growth of each strategy; `*_metrics.csv` = summary table | yes |
| `sentiment_eval.csv` | FinBERT vs VADER accuracy / macro-F1 on the labelled news set | yes (after Phase 8) |

## Sources and licences

1. **Synthetic sample data** - generated by `python scripts/make_sample_data.py` (fixed seed, reproducible).
   Headlines and tweets are filled from templates; each ticker gets a slowly drifting "story tone" so the
   rebalancer has something to react to. **They describe no real events** and are unrelated to real prices.
2. **GDELT DOC 2.0 API** - https://api.gdeltproject.org/api/v2/doc/doc - open, no key. Used in live mode.
   GDELT asks for at most about one request per 5 seconds; the loader batches companies into 3 queries.
3. **Kaggle - Sentiment Analysis for Financial News** (Ankur Sinha) -
   https://www.kaggle.com/datasets/ankurzing/sentiment-analysis-for-financial-news (licence: CC BY-NC-SA 4.0,
   derived from the Financial PhraseBank by Malo et al.). 4,846 sentences labelled positive/negative/neutral.
   No dates or tickers, so it is used to **evaluate** the sentiment model, not in the backtest.
4. **Kaggle - Stock Tweets for Sentiment Analysis and Prediction** (equinxx) -
   https://www.kaggle.com/datasets/equinxx/stock-tweets-for-sentiment-analysis-and-prediction
   (licence: as listed on Kaggle). ~80k tweets for 25 tickers, 30 Sep 2021 - 30 Sep 2022. Used for the
   historical backtest.
5. **Yahoo Finance via yfinance** - daily prices for research use, cached to `raw/prices.csv`.
6. **NewsAPI** (optional) - https://newsapi.org, only used if `NEWSAPI_KEY` is set in `.env`.

## How to get the Kaggle files

1. Sign in to Kaggle, open each dataset link above, click **Download**.
2. Unzip and copy `all-data.csv` and `stock_tweets.csv` into `data/raw/`.
3. Run `python run_pipeline.py --mode historical`, `python run_backtest.py --mode historical`
   and `python scripts/evaluate_sentiment.py`.

(Alternatively, with a Kaggle API token in `%USERPROFILE%\.kaggle\kaggle.json`:
`kaggle datasets download -d equinxx/stock-tweets-for-sentiment-analysis-and-prediction -p data/raw --unzip`.)

## Assumptions

- Universe: AAPL, MSFT, AMZN, GOOGL, META, NVDA, TSLA, NFLX, JPM, BAC, XOM, JNJ, PFE, KO, DIS.
- `GOOG` in the tweets data is mapped to `GOOGL`; `FB` to `META`.
- Not every one of the 15 names appears in the tweets dataset (the pipeline log prints counts per run).
  Stocks without signals keep neutral sentiment, so their weights move only through renormalisation.
- Historical tweets are capped at 25 per ticker per day (random, fixed seed) to bound CPU time.
- All timestamps are stored in UTC. The daily rebalance decision time is 20:00 UTC (16:00 New York).
- Prices are adjusted closes; no transaction costs, slippage or taxes.
